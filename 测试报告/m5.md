## 2. 设计要点（与 README §3.5 / §4.3 对齐）

- **向量默认关、可选开（D7）**：`vectorEnabled=false` 时零 embedding 依赖，行为与 M4 完全一致。
- **内容-向量分离绑定（§4.3 5.1）**：正文在 `facts`，向量在 `embeddings`（`ref_table='facts'` + `ref_id`），换模型重算只动向量表。
- **维度校验（§2.2⑥ 第 5 点）**：`EmbeddingClient` 对返回向量做 `assertDim`（必须 == 配置 `vectorDim`）；连接测试 dim 分项比对库中 vector 列维度；PG 侧 `vector(1024)` 列是最终防线。
- **RRF 合并（F-14）**：关键词 + 向量各取 limit×3 候选，`rrfScore = Σ 1/(k+rank)`，k=60；双来源命中（关键词+向量都召回）优先。
- **降级（R3）**：embedding 端点不可用 → `searchHybrid` 静默降级纯关键词，命令照常工作。

**验证中发现并修复的问题**：

1. **测试向量维度 4 ≠ 库列 1024**：`expected 1024 dimensions`——正是 §2.2⑥ 说的"维度不匹配写入失败"，PG 显式报错行为符合设计；测试向量改为 1024 维。
2. **1024 维纯随机向量无语义相关性**：改为「每字符固定随机方向求和」的确定性向量（共享字符多 → 余弦高），使检索断言可验证相对排序。
3. **Float32Array 精度**：`normalizeVector([3,4])` 得 `0.6000000238418579` 而非 `0.6`，断言改 `toBeCloseTo`。

## 6. 关键决策记录（本阶段）

- **D-M5-1 embedding 客户端缓存按 (baseUrl, model, dim) 元组重建**：设置保存后立即生效，不必重启；`vectorProvider` 每次命令执行调用 → 向量开关切换即时反映到 save/search。
- **D-M5-2 向量写入逐个失败不阻断入库**：向量是增强项，`persistFacts` 内单个 fact 的 embed/写入失败仅 console.error + 计数，事实本身已入库（避免「向量挂了记忆也存不进去」）。
- **D-M5-3 混合检索 embedding 不可用降级纯关键词**：`searchHybrid` 捕获 embed/向量查询异常 → 返回关键词结果（R3 缓解：远端故障不影响本地检索）。
- **D-M5-4 双来源各取 limit×3 候选再做 RRF**：RRF 需要足够深的 rank 才有区分度（rank 深 → 1/(k+rank) 衰减），浅候选会丢失长尾召回。
